## 硬性纪律

- 一切以计划文档为准；改架构/目录结构/工具链属重大决策，先出决策矩阵征求用户确认，再写 decision_log。
- **fuzzy 条目在 msgfmt 与 babel 两条编译路径下默认都不进 .mo**——任何构建前 fuzzy 必须为 0（`sphinx-intl stat` 退出码 1 即失败）；agent 修订 fuzzy 条目必须比对 `#|` 旧原文后清除标志。
- workdir 镜像布局不可变：`code/` 与 `src/` 同级、`include/uv/version.h` 就位；gen_workdir 后必须先跑英文构建冒烟再进翻译环节。
- 网络纪律：下载走 gh api / dist.libuv.org，直连失败按代理 `http://192.168.33.1:10808` 回退一次才可下结论；apt 等提权命令必须经 zcode-run 包裹（本机 WSL ubuntu2604）。
- 翻译批次（P1 起）验收门禁全绿才可合并：抽检 ≥10% 条目语义准确、术语 0 违规、fuzzy=0、零 error + 增量 warning 清零、linkcheck 通过；每批次/每次 sync 一个 commit（分支 PR + squash merge），便于 revert。
- 初译期间上游发新版：只开 issue 记录，不切基线（DR-004）。
- 批次收尾必更新 `docs/handoff-latest.md`；上下文过半或里程碑处（P0 完成 / P1 首发 / v1.0）主动建议开新会话并给交接提示词。
